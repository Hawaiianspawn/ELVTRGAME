# grows — so the ENTIRE incoming wave used to spawn outside the boundary, fully visible,
# striding. 4500 covers a typical wave with margin. It is not free: far more bodies now count

# have it live for long"). Sprays on SwarmAnim::HitFlashBit, read from the same render
# buffer the Niagara bridge already publishes — no sim change. Owner chose spray-on-
# every-hit knowing hits land continuously across the line; MaxBurstsPerFrame is the
# dial that keeps that choice from costing an unbounded amount. See
# docs/perf/blood-particles.md for the measured cost and verdict at wave-3 density.   @tab Unit
# ============================================================
Blood.Enable 1                 ; master on/off; 0 skips the scan entirely (zero cost off)
Blood.ParticlesPerHit 3        ; red pixels per burst, per struck unit found this frame.
                               ; DOWN from 6, 2026-07-28: at 6/24 (48 uu-6 particles per
                               ; frame, worst case) the bursts merged into one continuous red
                               ; smear across the fighting line at wave-1 density (370
                               ; entities) in an actual screenshot — see
                               ; docs/perf/blood-particles.md for the before/after images.
                               ; 3/12 reads as distinct clusters per hit with visible gaps.
Blood.MaxBurstsPerFrame 8     ; DOWN from 24, same wash fix. GLOBAL cap on bursts/frame —
                               ; the cost-bounding dial; without it cost scales with how many
                               ; units are mid-flash at once, which is unbounded at horde
                               ; density
Blood.Lifetime 0.5             ; seconds a particle lives — sub-second by design
Blood.Size 2                   ; sprite half-size uu — pixel-scale, not an fx-scale splat
Blood.SpeedScale 1.1            ; multiplier over NS_Blood's authored spray range; 0 = drops
                               ; straight down at the hit point. DOWN from 2.2 (owner-tuned
                               ; up from 1 for "punch" before the wash was found in a real
                               ; screenshot) as part of the same 2026-07-28 wash fix — 2.2
                               ; sprayed particles far enough to blur adjacent hits into each
                               ; other, which compounded the ParticlesPerHit/MaxBurstsPerFrame
                               ; smear. 1.1 keeps a little more life than the original 1
                               ; ("read flat/floaty") while not spreading far enough to bridge
                               ; gaps between hit points. See docs/perf/blood-particles.md.
Blood.HeightOffset 15          ; Z lift uu above the published (ground-plane) position

# HORDE ARRIVAL — where the tide comes from, in what ranks, and how ragged it lands   @tab Horde
# There is no distance culling on the renderer, so RadiusMin/Max are the only
# "how far out do enemies appear" numbers.
# ============================================================
Swarm.BroodSpawnRadiusMin 1200       ; [0..8000] inner radius of the spawn ring, uu — ALSO the
                                     ; radius of the FRONT rank in the formation below. DOWN from
                                     ; 2500 (iteration-speed tuning) — brood travel less distance
                                     ; before reaching the line, so waves reach real combat sooner.
                                     ; Still comfortably under Swarm.SimLOD.NearRadius (4500), so
                                     ; nothing spawns already strided
Swarm.BroodSpawnArc 120              ; [0..360] DEGREES of arrival, AND the sweep the brood rank
                                     ; formation fans its columns across. 360 = surrounded (used to
                                     ; be the default); ~90 = one flank; ~30 = a column down one
                                     ; approach. 120 = a broad FRONT — wide enough to read as a
                                     ; tide, narrow enough to leave flanks and rear clear
Swarm.BroodSpawnFaceCamera 1         ; 1 = the arc's centre bearing tracks the same heading the
                                     ; retinue faces (mirrors Formation.FaceCamera/Yaw), so "the
                                     ; front" survives the camera turning. 0 = ArcCenter below is a
                                     ; fixed world bearing, for a scripted encounter
Swarm.BroodSpawnArcCenter 0          ; [-180..180] +X=0, CCW positive. Extra bearing on top of the
                                     ; tracked yaw while FaceCamera 1 (mirrors Formation.Yaw); the
                                     ; bearing directly while FaceCamera 0. Ignored while Arc is 360
Swarm.BroodFormation.Columns 60      ; [1..200] brood per rank — same vocabulary as
                                     ; Formation.Columns, applied to the arc instead of the
                                     ; retinue's block. Wide reads as a broad front; narrow and
                                     ; deep reads as a column
Swarm.BroodFormation.RankSpacing 140 ; [20..400] radial gap between ranks, uu. Ranks step OUTWARD
                                     ; from RadiusMin (front rank leads, arrives first) — opposite
                                     ; sense from the retinue's Arc shape, which steps inward
                                     ; toward a bearer standing still
Swarm.BroodSpeedJitter 0.06          ; [0..0.8] per-brood speed variation, was 0.15. Lowered once
                                     ; the brood got ranks to arrive in: over the ~10s crossing,
                                     ; even a small per-unit gap compounds into hundreds of uu of
                                     ; drift, enough at 0.15 to blur ranks together well before
                                     ; contact. 0.06 keeps lines readable longer while still
                                     ; staggering the wave off one rigid frame

# ARMY-SCALE CAMERA — WHERE THE CAMERA ACTUALLY IS (docs/design/CAMERA-SCALE.md)   @tab Camera
# While Kindled.Cam.Scale is 1 or 2 (2 is the DEFAULT as of 2026-08-03) THIS section, not the
# GAME CAMERA block above, places the camera. One scalar — how much army you have left, 1 =
# full, 0 = alone — lerps width, pitch and distance between the two ends below, and swaps the
# projection at SwapAt. So every framing dial comes in a FULL / ALONE pair: set both to the
# same number to pin the shot regardless of army size, or spread them to make attrition move
# the camera. Mode 2 additionally measures the live retinue bbox and widens past whatever the
# scalar alone would give until it actually fits — see "strategic fit" below.
# ============================================================
Kindled.Cam.Scale 2                 ; DEFAULT as of 2026-08-03 (owner call): STRATEGIC. Was 0
                                      ; (pinned eye-level, GAME CAMERA block above — that shot is
                                      ; kept, not deleted; set this back to 0 to use it by hand).
                                      ; 0 = off — Cam.Ortho/OrthoWidth/Fov/Dist/Pitch drive the
                                      ; shot directly, no framing math at all.
                                      ; 1 = army-weighted — width/pitch/dist follow how much army
                                      ; is left (ScaleRetinueWeight/ScaleBroodWeight/ScaleBodies),
                                      ; a PROXY for where the bodies are, not a measurement.
                                      ; 2 = STRATEGIC — 1's scalar becomes a floor (see FitFloor)
                                      ; and the shot additionally widens until the live retinue
                                      ; bbox actually FITS (FitWidthMax/FitMargin). Contains your
                                      ; units; the brood is left to run off-frame on purpose.
                                      ; While 1 or 2, this OVERRIDES the five GAME CAMERA hand
                                      ; dials above every frame — they stop responding, by design

# --- strategic fit (Cam.Scale 2 only) ---
Kindled.Cam.FitWidthMax 7000        ; [2400..12000] hard ceiling on the strategic width, uu. Not a
                                      ; target — a view that grows without bound turns soldiers
                                      ; into pixels. Replaces ScaleWidthFull as the far end of the
                                      ; width lerp while Scale is 2; at 1920px a 48px soldier draws
                                      ; ~13px here, which still reads
Kindled.Cam.FitLog 0                ; 1 = log the solve once a second (extents / needs / at). The
                                      ; solve has NO other observable — PIE screenshots come back
                                      ; as the EDITOR viewport, so a picture cannot confirm it.
                                      ; This is the channel to tune the two dials below against
Kindled.Cam.FitMargin 1.15          ; [1.0..1.6] slack on the solved width. The bbox bounds unit
                                      ; CENTRES and is a frame behind, so 1.0 puts the outermost
                                      ; soldiers half-off the edge. Below ~1.05 the line clips
Kindled.Cam.FitFloor 0              ; [0..1] (src default, owner call 2026-08-04: "the units can
                                      ; be tighter together") how much of the weighted body-count
                                      ; scalar still floors the strategic width. 0 = solved from
                                      ; the measured retinue bbox alone — a tight huddle gets a
                                      ; tight, close, low shot however many bodies are in it. 1 =
                                      ; old behaviour, full retinue always pins width at
                                      ; FitWidthMax regardless of actual spread

# --- the FULL-ARMY end of the shot (scalar 1: you command a mass) ---
Kindled.Cam.ScaleWidthFull 2400     ; [400..8000] view width uu at full army — the zoom dial that
                                      ; replaces Cam.OrthoWidth while Scale is 1. INERT while Scale
                                      ; is 2 — FitWidthMax replaces this as the far width end there
Kindled.Cam.ScalePitchFull -55      ; [-90..-5] pitch at full army. -90 = the old straight-down
                                      ; map; -55 = tilted so the arena reads as ground you look
                                      ; ACROSS. TIED TO Swarm.SimLOD.NearRadius — shallower sees
                                      ; further down-field, so lower this and raise NearRadius or
                                      ; the LOD strides units that are on screen
Kindled.Cam.ScaleDistFull 1200      ; [200..6000] camera distance back along the view axis at
                                      ; full army. Under ortho this moves the clip planes, not the
                                      ; zoom — ScaleWidthFull is the zoom

# --- the ALONE end (scalar 0: the retinue is gone and you are a man) ---
Kindled.Cam.ScaleWidthAlone 700     ; [200..4000] view width uu with nobody left
Kindled.Cam.ScalePitchAlone -22     ; [-90..-5] pitch with nobody left — shallow enough to read
                                      ; as standing behind a person, not looking down at a token
Kindled.Cam.ScaleDistAlone 420      ; [100..3000] distance with nobody left; short enough that
                                      ; perspective actually bites
Kindled.Cam.ScaleSwapAt 0.5         ; [0..1] (owner-tuned, src 0.35) army scalar below which the
                                      ; projection HARD-swaps ortho to perspective. You cannot lerp
                                      ; one matrix into the other, but the FOV is solved from the
                                      ; same framing width, so only parallax changes across the
                                      ; cut. 0 = stay orthographic for the whole run

# --- the driver: how "how much army" is measured ---
Kindled.Cam.ScaleRetinueWeight 10   ; [0..50] pull of one live soldier on the scalar. Heavily
                                      ; outweighs the brood on purpose — YOUR attrition is the shot
Kindled.Cam.ScaleBroodWeight 0.25   ; [0..5] pull of one live brood. Small but non-zero, so being
                                      ; swarmed holds the shot a little wider
Kindled.Cam.ScaleBodies 1200        ; [100..6000] WEIGHTED total at which the scalar pins to 1.
                                      ; = RetinueCap(120) * RetinueWeight(10), so a full retinue
                                      ; ALONE reaches the wide end. Raise it above that and the
                                      ; wide shot becomes unreachable in normal play
Kindled.Cam.ScaleCurve 1            ; [0.2..4] shaping exponent on the 0-1 scalar. 1 = linear;
                                      ; >1 holds the wide shot longer then collapses late; <1
                                      ; descends early and eases out

# --- how the move FEELS (none of these change where the camera ends up) ---
Kindled.Cam.ScaleStiffness 3        ; [0..20] spring natural frequency rad/s. Eases INTO the move,
                                      ; not just out of it; settles in about 3/Stiffness seconds.
                                      ; 0 disables the spring and falls back to ScaleLerp
Kindled.Cam.ScaleDamping 1          ; [0.2..3] spring damping RATIO. 1 = critically damped, no
                                      ; overshoot. Below 1 rebounds past the framing, which reads
                                      ; as a mistake rather than as weight
Kindled.Cam.ScaleLerp 1.5           ; [0..20] plain FInterpTo speed on the scalar. ONLY USED when
                                      ; ScaleStiffness is 0 — the spring supersedes it
Kindled.Cam.ScaleStages 0           ; [0..12] 0 = continuous, so the camera is always subtly
                                      ; moving. N > 0 quantises the scalar into N steps so the shot
                                      ; SETTLES and only re-frames when a step is crossed. Try 4-5
Kindled.Cam.ScaleRatchet 0          ; 1 = one-way: the camera descends as the army dies and never
                                      ; rises again, even if a breather refills the retinue.
                                      ; 0 = reversible. Resets per run
