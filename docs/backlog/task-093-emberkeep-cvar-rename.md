## Why now
**This was filed as two tasks (093 CVars, 094 C++ types) and merged into one.** They
claimed identical directories — `ELVTR/Source/ELVTR/UI/**`, `Rendering/**`, `Spike/**`,
`Config/**` — and the type rename had to follow the CVar rename anyway, so splitting them
bought no parallelism and cost a second full editor-closed rebuild. One task, two phases,
one rebuild.

### Phase 1 — the console variables
102 CVar registration sites across `ELVTR/Source/` declare console variables under the
`Emberkeep.` prefix — `Emberkeep.Quantize`, `Emberkeep.Palette`, `Emberkeep.PaletteSteps`,
`Emberkeep.Cam.Yaw`, `Emberkeep.UI.*`, `Emberkeep.UnitCamProj.*` and the
`Emberkeep.Breadboard` panel command. These are the live tuning surface, so this is the
half of the purge that is a **real breaking change**, not a cosmetic one.

Three things break on rename and each needs handling rather than hoping:
`ELVTR/Config/SwarmExecOnPlay.canonical.txt` (the exec list, parsed by the Breadboard
panel), `Scripts/populate_cvar_preset.py` plus the `/cvars` skill, and two binary assets —
`ELVTR/Content/SwarmControls/CVP_UnitCam.uasset` and `SwarmConsoleVariablesAsset.uasset` —
which store CVar names as strings and must be **regenerated**, not hand-fixed.

### Phase 2 — the C++ reflected types
Five **reflected** types carry the dead name, and reflected types are not ordinary symbols
— Blueprints and `.uasset` files reference them by name, so renaming them without
`CoreRedirects` silently breaks asset links:

| Type | Kind | Blast radius |
|---|---|---|
| `UEmberkeepWidget` | UCLASS | base class of **six** widgets — `UMusterGrid`, `UMusterPanel`, `USquadCard`, `UStitchMeter`, `UUnitCamProjector`, `UEmberkeepHud` |
| `UEmberkeepHud` | UCLASS | the HUD |
| `EEmberkeepStance` | UENUM | 11 sites |
| `FEmberkeepSquad` | USTRUCT | 19 sites |
| `EEmberkeepMusterFlow` | UENUM | 8 sites |

Plus **eight files to rename** (`EmberkeepHud.cpp/.h`, `EmberkeepPalette.h`,
`EmberkeepUIDebug.cpp/.h`, `EmberkeepUITypes.h`, `EmberkeepWidget.cpp/.h`) and every
`#include` of them across ~20 files. `ELVTR/Config/` currently has **no CoreRedirects
section at all**, so nothing is catching renames today.
