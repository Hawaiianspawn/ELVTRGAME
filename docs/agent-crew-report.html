1 · The game, and why encounters are a budget problem

Kindled is a top-down roguelike in Unreal Engine 5.8. You carry the only fire in a pitch-dark world, and an army gathers in your light because outside it they die. You command that army through four broad stances rather than unit selection — three to ten units early, hundreds by late run.

That premise makes encounter design a budget question, not a taste question. Every enemy on screen costs draw time, and the project has a measured cost curve for exactly that (docs/perf/BUDGETS.md). The ceiling is hard: 16.6 ms per frame. A wave that reads well but cannot be drawn is not a design — which is why this crew contains an agent whose only power is to reject the designer's work.

3 · Architecture

4 · The six agents

Every agent reads a named key and writes a named key. Nothing is passed implicitly — an agent cannot read a key it did not declare, which is what makes the ordering load-bearing rather than incidental.

AgentRoleReadsWrites
canon-readerParses the project's shipped design and measured performance docs into one fact block, so no downstream agent invents a number. —canon
roster-architectDerives the tier ladder (fodder → soldier → elite → boss) as multipliers over the measured combat baseline, and prices each tier. canontiers
encounter-architectComposes the three escalating waves and the spawn cadence — and redesigns when an auditor sends the plan back. canon, tiers, revision_directiveplan
budget-auditorProjects peak concurrent entities onto the measured cost curve. Returns PASS, or REVISE with a scale directive the architect must obey. canon, planbudget_verdict, revision_directive
readability-auditorChecks each wave's simultaneous distinct silhouettes against the locked 4-value palette. canon, planreadability_verdict
data-emitterFlattens the approved plan into DataTable rows, writes the column schema, and refuses to emit anything that has not passed both audits. all of the aboveartifacts

Why no agent is removable

canon-reader — every downstream number becomes invented. The crew would still run and produce a plausible-looking encounter with no grounding in the game.
roster-architect — the encounter architect has bodies but no tiers to compose from, and no per-tier cost to be audited against.
encounter-architect — nothing produces a plan; both auditors and the emitter have no input.
budget-auditor — the crew emits encounters it cannot draw. This is the agent that actually fired on the latest run, forcing a redesign.
readability-auditor — waves ship that are affordable but unparseable at speed, which the 4-value palette makes a real failure mode rather than a hypothetical one.
data-emitter — verdicts exist but nothing reaches the game. No artifact is produced at all.

6 · How the output reaches the game

encounters.json is emitted flat and typed, with one unique row key per entry, so it imports directly as an Unreal DataTable — the same shape the project's other design data uses. The schema file states each column's units and valid range, so a designer changing a number by hand knows what they are changing.

The connection runs both ways, and that is the point: the crew reads the game's real measured files and writes data the game consumes. It is not a general-purpose encounter generator pointed at a game — it is grounded in this project's own numbers, and its budget verdicts are only meaningful because those numbers were measured rather than assumed.
